# Revisión Haiku: leads-sales

Review done, but I did not write `docs/revision/haiku-leads-sales.md`: the subagent rules forbid report .md files, so the findings are below instead. Nothing was edited.

Findings, most severe first (file:line are in `app/leads/` unless noted):

1. **High: naive datetime-local timestamps are read as UTC.** `sales_router.py:243` takes `first_reply_at` as a naive datetime, and `secret_shop.py:199` passes it through `ensure_utc` (`app/core/clock.py:22`), which treats it as UTC. Operators in Bogota (UTC-5) get `response_seconds` off by 5 hours, which corrupts the outcome and the pitch evidence. Fix: localize the form value to `BOGOTA` before converting to UTC in `ui_reply`. No test covers the timezone case.
2. **Medium-high: check-then-insert races on single-use rules.** `secret_shop.py:148-149` ("solo una vez") and `secret_shop.py:197-198` (double reply) are app-level checks. `app/db/models/leads.py:161-185` has only a non-unique index on `lead_id`, so concurrent POSTs create duplicate tests. The same pattern appears in `demo.py:157-184` (duplicate demo tenants) and `demo.py:273-276` (double conversion). Fix: a partial unique index on `secret_shop_tests(lead_id)` and a row lock (`SELECT … FOR UPDATE`) on the lead in `pipeline.get_lead` for write paths.
3. **Medium: `expires_at` is wrong on reuse.** `demo.py:154` and `demo.py:164` return `now + TTL` even when reusing a token minted earlier, so the UI ("Vence el …", `_acciones.html`) shows a later date than the link actually has. Fix: store the mint time in the token payload, or compute expiry from the tenant's token.
4. **Medium: do-not-contact leads can get demo links.** `demo.py:150` blocks only `perdido`, while `convert_lead` (`demo.py:273`) requires `activo`. Fix: use `if lead.disposition != "activo"` in `lead_to_demo_bot`.
5. **Medium: public demo chat can burn LLM quota.** `demo.py:251-258` caps messages per tenant only (30 per 7 days), with no per-IP or per-session throttle, and each message calls `sandbox_reply`. `sales_router.py:355-365` catches only `AppError`, so LLM or factory failures surface as raw 500s on a public page and the typed message is lost. Fix: add an IP-keyed limit and catch `Exception` with a generic Spanish error.
6. **Medium: SSRF and blocking I/O are not verified.** `demo.py:188` runs `build_bot(..., scrape=True)` synchronously inside the request, and `factory/service.py:134-145` scrapes `lead.website`. I did not verify that the scraper blocks private IP ranges. Fix: confirm the scraper's URL guard, and move scraping to a background job.
7. **Medium (performance): the timeout job is N+1 and unbounded.** `secret_shop.py:242-256` loads every unanswered test, then runs `rescore` (two queries), `session.get`, and an event insert per row. `pending_reviews` (`secret_shop.py:270-284`) has no `LIMIT`. Fix: batch with `UPDATE … RETURNING` and chunked processing, and add a limit to `pending_reviews`.
8. **Low: silent failures.** `secret_shop.py:86-89` treats unparseable Places `periods` as after-hours without logging. `expire_unanswered` (`secret_shop.py:233-256`) writes no audit log, unlike every other transition. `pipeline.py:75` with negative `limit` produces an SQL error.
9. **Low (UX/copy): the reply form has no timezone hint or default.** `_acciones.html` `ps-at` has no "hora de Bogotá" label, default value, or `min`. Empty and error states are otherwise handled, and CSRF is correctly enforced under `/admin` and `/api` only, leaving the public `/demo` routes exempt.

Tests: none cover the datetime timezone, race, expiry, or `no_contactar` demo cases (grep of `tests/leads/test_sales_*.py`).
